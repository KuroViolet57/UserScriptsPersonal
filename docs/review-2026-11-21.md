# Vault review — 2026-11-21 (commit 89868ea)

Scope: Tab Vault (extension `tab-manager/` 1.13.0 + `tab-vault.user.js` 1.0.0) and Media Vault
(extension `media-sniffer-ext/` 1.6.0 + `media-vault.user.js` 1.0.0). Read-only review; nothing changed in code.

How each finding was checked (column "Check"):
- **Reproduced**: run against the real file in Node with a fake `chrome` API (scripts described below).
- **Code read**: the lines were re-read in this session and say what the finding says; behaviour not run in a browser.
- **Reviewer**: reported by a fresh reviewer with file:line; not re-read in this session.

## Tab Vault

### Fixes
| # | Where | Severity | Check | Problem → fix |
|---|---|---|---|---|
| T1 | `tab-manager/background.js:123-137` (`pushClosedTab`), `:99-121` (`pushClosedWindow`) | High | **Reproduced** | Each close does read list → add → write with no queue. Closing many tabs at once ("close other tabs", bulk close) keeps only one. Test: 10 tabs closed at the same moment → `closedTabs=1`; the same 10 closed one by one → `closedTabs=10`. Fix: run all closed-list changes through one promise queue in the worker. |
| T2 | `tab-manager/manager.js:1449-1460` (`reopenWindow`), `:1660-1661` (New window) | High | Code read | Runs in the toolbar popup. `windows.create` focuses the new window, which closes the popup and stops the loop that adds the remaining tabs and groups. Fix: do it in the worker (like `runOpenJob`) or create with `focused:false`. |
| T3 | `tab-manager/manager.js:1691-1695` + `renderClosed` `:564-567` | Medium | Code read | Search runs `render()` on every keystroke; `renderClosed` clears then awaits storage, so overlapping renders append rows twice and break range-select. The userscript already guards this with `renderSeq` (`tab-vault.user.js:1466-1477`); port it + debounce. |
| T4 | `tab-manager/manager.js:1230-1251` (`importData`) | Medium | Reviewer | No shape check (a session without `tabs` blanks the section); imported items are appended unsorted and later trimmed away by `slice(0, max)`. Fix: validate like the userscript's `hasTabs/hasUrl`, sort by `closedAt`, cap on import. |
| T5 | `tab-vault.user.js:2476-2484` + `writeLive` `:272-281` | Medium-high | Reviewer | Every tab rewrites one shared `live` object, so a closing tab's "gone" mark can be overwritten by another tab's heartbeat; the closed tab then shows as open until the stale timeout. Fix: one GM key per tab. |
| T6 | `tab-vault.user.js:371` with `:491-499` | Medium | Reviewer | After a duplicated tab gets a new id, the command listener still watches the old id; remote close/focus stops answering (Violentmonkey path). |
| T7 | `tab-manager/background.js:232-247` | Low-medium | Reviewer | A batched restore that dies with the worker leaves the progress bar stuck forever; remaining URLs are not saved. |
| T8 | `tab-manager/manifest.json:40-48` | Medium | Code read | `manager.html` is web-accessible to all sites under a fixed ID, so any site can frame it (clickjacking on Close/Clear) or detect the extension. Fix: `use_dynamic_url: true`. |
| T13 | `tab-manager/manager.js:1026` | Low | Code read | Batch delay 0 saves as 3 (`+value || 3`). |

### Performance
| # | Where | Severity | Check | Problem → fix |
|---|---|---|---|---|
| T9 | `tab-manager/background.js:147-149`, `slimTab :49-55`, `content.js:29` | Medium-high | Code read | Every title/URL/load change rewrites the whole tab mirror (with favicon URLs, often data: URIs) to `storage.local`, and every open page's content script receives the change. Fix: keep the mirror in `storage.session`, drop data: favicons, skip title-only rebuilds. |
| T10 | `tab-vault.user.js:445-457` (`logPage`), callers `:2502`, `:2529` | Medium-high | Code read | The whole History log is read and rewritten on each title change, not debounced. Fix: debounce per tab and skip unchanged writes. |
| T11 | `tab-vault.user.js:2506-2517` (heartbeat) | Medium | Reviewer | Each tab rewrites the full `live` map and runs a sweep every heartbeat; traffic grows with tabs², and an open sheet re-renders on every write. Fix: per-tab keys, write on change, sweep from one tab. |
| T12 | `tab-manager/manager.js:1432-1446` (`restoreGroup`) | Medium | Reviewer | Creates every tab before discarding any, so a 100-tab group loads 100 pages at once; runs in the popup. Fix: move to the worker and discard each tab right away. |

### Improvements
- T14 `tab-manager/content.js:59-127`: the in-page sheet is not in a shadow root, so site CSS can hide or restyle it (the userscript uses a closed shadow root). — Reviewer
- T15 `popup-size.js:49-58` (shared by both extensions): the boot watchdog catches `error` but not `unhandledrejection`. — Reviewer
- Live Open list: the manager does not listen to `tabs.*` events, so the list goes stale while open. — Reviewer

## Media Vault

### Fixes
| # | Where | Severity | Check | Problem → fix |
|---|---|---|---|---|
| M1 | `media-sniffer-ext/background.js:130-141` (`loadMedia`) | High | **Reproduced** | When the worker wakes, several detections arriving together each load the list and replace it, dropping items. Test: 5 detections at once on a cold worker, 20 runs → 17 kept 5, 3 lost some (kept 2, 3, 4). Fix: cache the load promise. |
| M2 | `background.js:279-283` | Medium | Code read | Per-tab list is cleared only when `info.url` is set; Chrome's tabs docs say `url` is sent only when it changed, so a reload keeps the old list (README says it resets). Fix: clear on top-frame `loading`, or use `webNavigation.onCommitted`. |
| M3 | `background.js:110`, `142-151` | Medium | Reviewer | Buckets of tabs that were open at browser exit are never pruned and the whole map is rewritten every 500 ms during playback. Fix: prune on startup against `tabs.query`, write only changed buckets. |
| M4 | `media-vault.user.js:2010` (`window.__MV`) | Medium | Reviewer | Exposes `set()`/`addItem`; where the script shares the page's `window`, a site can turn detection off everywhere or change the player/download package names that go into intent URLs. Fix: debug flag only, validate package names. |
| M5 | `background.js:163`, `media-vault.user.js:265` | Medium | Code read (ext) | Dedupe on full URL: playlists re-polled with changing query strings (LL-HLS `_HLS_msn`, tokens) fill the list to `maxPerTab` and push out real files. Fix: dedupe streams on origin+path. |
| M6 | `background.js:73-75` | Medium | Reviewer | Segments without a file extension (`video/mp2t`, fMP4) are labelled "mp4" and not folded; the extension lacks the userscript's segment-name heuristic. |
| M7 | `background.js:328` (`name: it.title || …`) | Medium | Code read | Page-detected media is named after the page title with no cleaning and no extension; `/` makes subfolders, and every item on a page gets the same name. The userscript's `makeName/sanitizeName` already handles it. |
| M8 | `media.js:341-348` | Medium | Code read | Bulk **Remove** filters `state.items`, then `render()` → `loadItems()` reloads them from the worker, so removed rows come straight back. |
| M9 | `content.js:59`, `:72-73` | Low-medium | Reviewer | `reported` set never resets, so page-only (blob/cached) media never reappears after Clear. |
| M10 | `background.js:251-255` | Low | Reviewer | A 206 response with `Content-Range: …/*` stores the chunk length as the file size. |
| M11 | `media-vault.user.js:591-592` | Low | Reviewer | Reads `content-range` on every cross-origin XHR before checking it is media. |

### Performance
- M12 `background.js:243-270`: `onHeadersReceived` has no `types` filter (`{ urls: ['<all_urls>'] }` only — **code read**), so every image/script/font response wakes the worker; each media hit also reads settings twice. Fix: add `types`, cache settings, debounce the badge.
- M13 `media.js:162-165`, `:564`: each search keystroke sends three messages and rebuilds the list. — Reviewer
- M14 `media-vault.user.js:2008`, `:526`: runs in every iframe (ads too) with a permanent 1.5 s scan and a 10 s hello broadcast; `mvf_o_<origin>` keys are never deleted. — Reviewer

### Improvements
- M15 `content.js:11`: content script is top-frame only, so embedded players get no on-video button and their blob sources are missed. — Reviewer
- M16 `media-vault.user.js:931`, `:940-941`: the debug console evals the latest `eruda` from jsDelivr with no version pin. — Reviewer
- M17 `manifest.json:39-47`: `media.html` web-accessible under a fixed ID; use `use_dynamic_url`. — Code read (same pattern as T8)
- M18 Referer for extension downloads: `chrome.downloads` cannot set Referer, hotlink-protected hosts can refuse; a short-lived declarativeNetRequest rule could add it. — Reviewer
